Overview · socle V2 + cible V3

Une stack de jeu native, ouverte par un langage vivant.

Le cœur reste C++/Qt et host-authoritative. V3 ajoute une surface MCP, des agents supervisés et un pipeline d’exécution QML/JS gouverné.

Choix structurantLe QML n’est plus seulement l’interface du jeu : il devient, avec le JS embarqué, un support de gameplay créé au runtime.

Fiches technos

À quoi sert chaque famille

Application

Qt 6.11 / C++20

Le socle multiplateforme : Core, Quick, QML, Network, WebSockets, SQL, Quick3D, Concurrent et CanvasPainter. V3 requiert aussi QtHttpServer.

Expérience

QML / Qt Quick / JS

L’UI et la scène sont déclaratives. Le caractère interprété permet aux artefacts validés d’ajouter comportement et présentation sans recompilation.

3D & physique

Quick3D + Pattounx

Quick3D charge les GLB et présente les acteurs ; Pattounx simule collisions, zones et corps dans un thread physique dédié.

Réseau

Catway / UDP / STUN

Le P2P traverse les NAT et transporte les domaines Game, Editor et Physics. Les commits V3 ajoutent ACK, retry et déduplication applicatifs.

IA locale

MCP + HTTP + JSON-RPC

Une surface de tools curée relie les agents au jeu. Le canal reste strictement loopback et distinct de l’automation de test.

Isolation

QProcess + QQmlEngine

Le banc démarre un moteur QML séparé et jetable ; l’exécution en jeu utilise un contexte restreint et la façade Meow.GameApi.

Services

Node.js / WebSocket / SQLite

Le chat conserve son serveur Node et sa base SQLite, avec relais chiffré de bout en bout. Ce n’est pas le canal IA.

Contenu

GLB / AssetManager

Les assets officiels utilisent le pipeline existant, enrichi par version, hash, dépendances et manifeste de package V3.

Build

CMake / Ninja

Build multi-config, Qt 6.11 et MinGW 13.1 sous Windows. La qualification et le packaging Linux restent un chantier transversal.
