Parcours nominal

Les 9 étapes d’une proposition

L’enveloppe de proposition est l’unité auditée qui relie tout le parcours.

01

Le joueur formule son intention

Le tchat ingame invoque l’agent ; aucun CLI n’est manipulé directement par le joueur.

02

L’application prépare l’IA cliente

Spawn supervisé, token proposer, configuration MCP et skill injectée en pré-prompt.

03

L’IA observe puis compose

state_query, screenshot si utile, puis primitives existantes + mémoire + JS embarqué.

04

La passerelle construit l’enveloppe

Auteur, intention, opérations, artefacts, versions et write-set. Le requestType est recalculé mécaniquement.

05

Le préfiltre P0 ferme les portes évidentes

Schéma, quotas, source ≤ 20 KB, imports et fonctions interdits. Un échec est immédiatement actionnable.

06

L’arbitre juge la viabilité

Le code et les règles passent toujours ici. Verdict : accepter, amender ou rejeter. Les raisons ciblent le joueur et l’IA.

07

Le banc d’essai valide le comportement

Snapshot de carte, moteur QML distinct, phases P1→P5. Boucle infinie ou crash : le process de test meurt, jamais le jeu.

08

L’hôte applique atomiquement

Staging, validation du write-set, commit autoritatif puis journalisation. Toute l’enveloppe passe ou rien ne passe.

09

Les pairs observent un résultat validé

Effets répliqués, état mis à jour, verdict injecté au prochain tour. L’IA cliente relit et itère si nécessaire.

Branches de décision

Accepter, amender ou rejeter

✓ Acceptée

Application directe après le banc

La version validée devient autoritative, avec versions résultantes et métriques inscrites au journal.

✎ Amendée

Jamais de passe-droit

Si l’arbitre modifie le code, la version amendée repasse obligatoirement au banc. L’original reste dans l’audit.

× Rejetée

Une erreur qui permet d’avancer

Code stable, message clair, détails et indicateur retryable. L’IA corrige et re-propose.

Frontière essentielle : l’arbitre juge la cohérence, l’équilibre et l’abus potentiel. Le sandbox, les quotas, le protocole et l’autorité hôte garantissent la sécurité et l’intégrité. Les deux fonctions ne sont jamais interchangeables.
